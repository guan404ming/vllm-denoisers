# Deviations from the HF reference

- Sampler: receives hidden states and runs the LM head itself. `low_confidence` projects only still-masked positions and nothing on the commit step, unless logprobs or the probe need the whole block. Other policies project every position; `joint` and `indel` skip commit rows.
- Sampler kernels: on the greedy path, one fused Triton row-stats kernel reads the logits once for argmax, confidence, and entropy. With `temperature > 0`, a second kernel reads the logits once, then reads only the vocabulary tile that holds its inverse-CDF draw. It also gives the untempered probability that LLaDA-8B ranks by. Per-request top-k/top-p use the torch path on the same positions.
- Sampling: greedy unless the HF config sets `temperature`. Per-request top-k and top-p apply; penalties and seeds are ignored; the mask token is never sampled. The indel anti-loop and the Fast-dLLM block seed always take the argmax.
- Sampling noise (`low_confidence`, `fast_dllm`, `dream`, `llada` with `temperature > 0`): each draw is the inverse CDF at a counter hash of request order, canvas, step, and cell.
- Logprobs: from the commit forward over the finished block (teacher-forced), not from the step that unmasked each token. DiffusionGemma differs, see [diffusion_gemma.md](diffusion_gemma.md).
- Indel anti-loop: resamples the lowest-confidence changed position, not a random one.
- LLaDA2.2 tokenizer: plain `PreTrainedTokenizerFast`; no tool-to-TypeScript rendering, no long-text chunked encode.
- LLaDA2.1 reference: passes a 0/1 float mask that transformers 5.x applies as-is; `llada2_eval.py` converts it to 0/-inf.
- Fast-dLLM v2: the first token of a block comes from the previous block's last position. When the prompt length is a multiple of 32 there are no prefill logits, so slot 0 of the first block is predicted from its own position.
- Dream: matches the HF loop step for step while prompt plus response fit in one canvas. A longer prompt keeps only its last `len % canvas_length` tokens in the canvas; the rest is prefilled bidirectionally once and never sees the response, which costs accuracy. A response longer than the canvas runs as further blocks. `alg` is always `entropy` with `alg_temp` 0. With `temperature > 0`, `top_p` comes from the HF config and the ranking entropy is that of the top-p nucleus of the scaled softmax, as in the reference. The nucleus holds only tokens with scaled probability of at least 1/256, and always the most likely token, so a nucleus that needs smaller tokens is cut short. Only rows that predict a masked position are read. Do not also pass a per-request `top_p`.
- LLaDA-8B: matches the reference while prompt plus response fit in one canvas. Sub-blocks count from the response start, and with `temperature > 0` sampled tokens rank by their untempered probability, as in the reference. A longer prompt keeps only its last `len % canvas_length` tokens in the canvas; the rest is prefilled once and never sees the response, which costs accuracy. The response region is the canvas minus the prompt tail, not `max_tokens`, so a region much longer than the reference `gen_length` gives longer answers that `max_tokens` cuts off.
- Final prefix exit (`low_confidence`, `fast_dllm`, `dream`, `llada`): a canvas ends when every cell before its first stop token is unmasked. The reference decodes the cells after the stop token too; the engine cuts the text at the stop token, so the text is the same. The exit removes later rows from the batch, so bf16 results of the other rows can differ.
- `pruner: "masked"`: inside a block, a position's K/V is recomputed on the step after it is unmasked and then frozen until the commit step recomputes the block. The reference recomputes every position every step.
